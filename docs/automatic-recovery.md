# YouTube 自动修复机制

本项目把常见的 YouTube 下载失败分成“可以自动恢复”和“不能盲目重试”两类。

## 可以自动恢复的错误

下载器会自动处理下面这些临时错误：

- HTTP 403、408、429、500、502、503、504
- 连接超时、读取超时
- 连接被重置或中断
- DNS 临时解析失败
- 网络暂时不可达
- 分片传输中断或读取不完整

视频不存在、链接不合法、明确的权限拒绝等错误不会无限重试。

## 视频回退顺序

每次尝试都会重新创建 yt-dlp 下载器，避免继续使用已经过期的媒体地址。

1. **默认最佳线路**：保留用户选择的画质、编码和格式。
2. **刷新授权地址**：重新解析视频，获取新的媒体签名和 CDN 地址。
3. **mweb 线路**：使用 YouTube `mweb` 播放器客户端并优先使用 IPv4。
4. **匿名兼容线路**：移除 Cookie 和认证请求头，切换到 `android_vr`。
5. **兼容合并格式**：优先选择本身同时带视频和音频的流，减少合并和转码失败。

只有前一步确实遇到可恢复网络错误时，才会进入下一步。普通参数错误不会被格式切换掩盖。

## 自动格式原则

- 自动模式优先最佳可用画质。
- 自动模式优先非 AV1，降低老设备和编辑软件的兼容问题。
- 如果只有 AV1 可用，仍允许自动回退，不会直接判定失败。
- 最后兼容回退可能得到 WebM、MKV 或 MP4，具体由视频实际提供的格式决定。
- 本项目不承诺所有视频都保存为 MP4；强制容器格式反而可能降低成功率。

## 并发和更新

- 默认并发数为 2，避免批量订阅同时请求 YouTube 时更容易触发临时限制。
- 每次解析之间有短暂间隔。
- 默认每天凌晨 04:15 更新 yt-dlp nightly，减少长期使用旧解析器造成的失败。

## AI 的作用

AI 不参与下载决策。AI 服务不可用、密钥无效或超时时，固定回退链仍然照常工作。
